# 数据结构：采集报告 / 校验输出 / 授权文件

全部 JSON 均为 UTF-8 文本。本文档对应 hwfp 0.1.x（报告 schema v1、授权 schema v1）。

## 1. 采集报告（hwfp.exe 默认输出 / Hwfp_Collect 返回）

```json
{
  "schema_version": 1,
  "tool":     { "name": "hwfp", "version": "0.1.0" },
  "generated_at": "2026-09-18T03:21:07Z",        // UTC，仅审计，不参与指纹
  "elapsed_ms": 212,
  "channels": { "available": ["native","registry","smbios","wmi"], "unavailable": [] },
  "fingerprint": {
    "algo": 2,                                     // 算法版本戳（见下）
    "master": "<64 位大写十六进制>",
    "master_short": "<master 前 32 位>",
    "sub": { "bios": "<64hex>", "board": "...", "cpu": "...", "disk": "...",
              "gpu": "...", "memory": "...", "nic": "...", "os": "...", "sys": "..." }
  },
  "fields": [
    { "key": "board.serial", "index": 0, "ok": true, "placeholder": false,
      "value": "…", "channel": "smbios",
      "confidence": "high",
      "note": "…" }                                // 仅在诊断信息存在时
  ]
}
```

- `fingerprint.algo`：指纹由「字段集 + 权重 + 规范化规则」共同决定，任一变更都会递增。
  `--verify` 遇报告与当前算法版本不一致时输出 `algorithm_changed:true`、
  `integrity:null` 并以退出码 4 结束（区别于"报告被篡改"的退出码 3）。
- `fields[].confidence`（仅在多通道有值或交叉验证发生时出现）：
  `high`=跨通道值一致 / `fallback`=多通道分歧取最高优先级 /
  `single`=未做交叉验证——FirstByPriority 系字段多通道有值时取最高优先级，
  或 Aligned 系实例仅单通道提供。
- 多实例字段（disk.\* / memory.\* / nic.\* 等）按 `index` 排布；磁盘与网卡为逐实例
  对齐口径（`instance_key` 分别为盘位号与 MAC，不直接出现在报告中，体现在
  confidence/note 与实例配对上）。

## 2. `--verify` 输出

```json
{
  "master": "<重算整机指纹>",
  "old_master_recorded": "<报告记录值>",
  "old_master_recomputed": "<报告字段回读重算值>",
  "algo": { "recorded": 2, "current": 2 },
  "algorithm_changed": false,
  "weights_override": false,
  "integrity": true,        // recorded == recomputed；算法不一致时为 null
  "match": true,            // 两侧整机指纹是否相同
  "similarity": 1.0         // 组权重相似度 ∈ [0,1]
}
```

退出码：0 完整性通过；3 篡改或采集失败；4 算法版本不一致（完整性不可判定）。

## 3. 授权校验输出（`license --check` / Hwfp_CheckLicense）

```json
{
  "valid": true,
  "format_ok": true,
  "signature_ok": true,
  "bound": true,             // 授权是否绑定机器
  "binding_checked": true,   // 绑定授权且实际做了本机比对才为 true
  "binding_ok": true,
  "expired": false,
  "similarity": 1.0,
  "threshold": 0.85,
  "licensee": "…",
  "issued_at": "2026-09-18",
  "expires_at": "2099-01-01",
  "reasons": []
}
```

退出码：0 有效；5 格式或签名无效；6 已过期或机器不匹配（DLL 返回码同语义）。

## 4. 授权文件（schema v1）

JSON 外壳 + 对 canonical 文本的 RSA-2048（SHA-256，PKCS#1 v1.5）签名：

```json
{
  "license": {
    "schema": 1,
    "licensee": "客户标识",
    "issued_at": "YYYY-MM-DD",
    "expires_at": "YYYY-MM-DD 或空串（永久）",
    "fingerprint": "<64hex 整机指纹，空串=浮动授权>",
    "sub": { "board": "<64hex>", "cpu": "…" },
    "features": { "seats": "5" },
    "nonce": "<签发侧随机 hex>",
    "sig": "<base64 签名>"
  }
}
```

签名覆盖的 canonical 文本（签发与校验两侧按同一规则重建，与文件字节序无关）：

```
HWFP-LICENSE-V1
licensee=<客户标识>
issued_at=<日期>
expires_at=<日期或空>
fingerprint=<64hex 或空>
sub=<组=子指纹;…>          按组名升序
features=<k=v;…>           按键升序
nonce=<随机串>
```

防篡改：`sub`/`features` 参与签名，改动任一字段即验签失败；值域禁止换行与
`;`/`=`（canonical 注入防线，签发与解析两侧同拒）。机器绑定校验 = 重算本机指纹
与 `sub` 做组权重相似度，≥ 阈值（默认 0.85，`--threshold` 可调）视为同一台机器。
